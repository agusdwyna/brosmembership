# Taste
- Writes requests in Indonesian (e.g. "bantu cek kenapa gagal login", "kenapa tiap aku login aku buka devtool ... gak ada ya hit api", "lanjut") and expects replies in Indonesian. Confidence: 0.75
- Asks short, terse questions in a conversational tone and expects the agent to autonomously explore the codebase, reproduce the issue, find the root cause, fix it, and verify the fix before reporting back. Confidence: 0.65
- When tests fail, does not accept "it's pre-existing / unrelated to my change" as an answer — wants the failure traced to its actual root cause (dependency/version/env chain) and fixed ("telurusuri coba"). Confidence: 0.55
- For broad changes (e.g. refactors, cross-cutting consistency cleanups), wants an audit/report first before any edits ("cari lalu laporkan dulu") — inspect the codebase, catalog the inconsistencies, and present findings plus recommended direction, then wait for approval before applying changes. Confidence: 0.75
- Wants audits to be exhaustive and end-to-end — every route, every function, the full business flow, and verified through to the actual browser UI ("audit full semua route, semua fungsi, alur bisnis sampai ke tampilan browser"), with findings grouped by severity and prioritized, not just a static code review. Confidence: 0.65
- For new feature work that involves design decisions, wants the approach discussed and agreed up front — explicitly asks to weigh the best mechanism, naming (e.g. status names), and data model before code is written ("diskusi dlu gimana mekanisme pendekatan terbaik, nama status dll"). Confidence: 0.7
- Values consistency across reused/shared components: uniform widths, heights, spacing, focus/error states, and alignment (e.g. form containers) instead of ad-hoc per-page values, and prefers consolidating duplicate/dead components into a single canonical implementation. Confidence: 0.6
- Canonical project UI conventions: form/page containers are FULL WIDTH — never constrained with `max-w-*` / `mx-auto` (no `max-w-2xl` on form pages); forms should fill the content area like list/table pages. The standard interactive control height is `h-9` (36px) for Input, Select, Button size="md", and toolbar SearchInput; `Button size="sm"` (`h-8`) is reserved for in-table row actions. Confidence: 0.8
- Exception to the full-width rule: the Scanner page keeps its original focused/centered column layout (`max-w-2xl mx-auto` container, `max-w-lg` camera, `max-w-md` input/button) — it should NOT be made full width. Confidence: 0.7
- Wants user-facing UI copy/labels in Indonesian (Bahasa Indonesia), consistent across all pages — approves standardizing English strings (titles, buttons, column headers, filters, empty states, dialogs, toasts) to Indonesian rather than mixed EN/ID. Confidence: 0.7
- Expects permission-based gating at the action level, not just route-level: action buttons/controls (add, toggle, edit) should be hidden or disabled when the user lacks the relevant permission (e.g. via a `useCan(permission)` helper), rather than relying only on route guards plus a 403 toast. Confidence: 0.55
- Is frustrated by terminal commands that hang/freeze mid-work ("terminal command code hang ... kecewa itu freeze ditengah pekerjaan") — wants commands run non-blocking/with timeouts so the session never stalls, and expects interrupted work to be tracked and resumed immediately ("lacak pekerjaan itu skrg"). Confidence: 0.5
- Once work is verified green (builds, lint, tests, migrations), expects the agent to commit AND push it — a single-word "continue"/"lanjut" or a terse "oke ubah lalu push" is enough authorization, with no separate diff walkthrough or confirmation before pushing to origin. Confidence: 0.6
- Wants commit messages SHORT: a single sentence in English (not a conventional multi-line body with bullet points), e.g. "commit dengan pesan singkat 1 kalimat berbahasa inggris"; the commit and push should just be done, then reported back briefly in Indonesian. Confidence: 0.7
- Personal account features belong in the header, not in Settings: profile info and self-service change-password should live under a user menu in the top-right corner of the header (click name → dropdown with Profil / Ganti Password / Keluar), and a "Profil" tab inside Settings is unwanted. Confidence: 0.8
- Moving a feature is not enough — when relocating something (e.g. the profile menu to the header) the user expects it completed end-to-end, including finishing the unfinished part of the feature (e.g. actually implementing the change-password flow). Confidence: 0.65
- Expects seeded/system roles to actually carry the permissions their description implies (e.g. an OFFICER "who scans and records visits" must have `visit.create`/`visit.view`), so permission-gated actions are not silently invisible to the roles meant to use them; when a feature "doesn't exist" in the UI, check role/permission config and stale session data before assuming the control is missing. Confidence: 0.5
- Corrects the agent bluntly and briefly in Indonesian when it picked the wrong next task ("nope task terakhir tadi ...") and restates the actual scope in one line; the agent should follow the corrected scope rather than re-litigating it. Confidence: 0.6
- Deploys to a self-hosted Coolify instance from a single-service Dockerfile ("deploy dockerfile 1 servie di coolify"), with all configuration injected as runtime environment variables through Coolify's Environment Variables UI — never a committed/committed-adjacent `.env` on the server. Deployment config should be built around that: no secrets baked into the image, Dockerfile must be self-sufficient (generated Prisma client, prod-only deps plus runtime tools, healthcheck, public port 80), and health/volume/port requirements must be stated explicitly for Coolify. Confidence: 0.7
- For deploy prep, wants a ready-to-use env template rather than instructions to write it: secrets (JWT_SECRET, seed passwords) pre-generated strong/random, real domain-specific values left as clearly marked `GANTI-…` placeholders, Indonesian explanatory comments inline, and the file itself kept out of git and out of the Docker build context. Confidence: 0.5
- Wants deployment/infra work delivered with a written Indonesian guide in the repo (`docs/DEPLOY.md`): step-by-step Coolify setup, the exact env-var block to paste, verification steps, and a troubleshooting table — not just the changed config files ("gas berikan panduannya juga", "simpen di deploydocs"). Confidence: 0.65
- Treats that in-repo doc as a handoff artifact: it must stand alone and be resumable after a break ("karena saya mau pulang"), so it should open with a terse actionable checklist (checkbox steps, the do-NOT-do warnings) before the detailed sections, rather than requiring re-reading the whole file or asking the agent where things stand. Confidence: 0.55
- Expects every meaningful business entity/data type to be surfaced in analytics, not just on its operational page — new data (e.g. kunjungan/visits) must land in dashboard KPIs, chart series, and report KPIs/trends/tables ("kunjungan masukin di grafik dan report"), implemented as one end-to-end slice across backend aggregates, API types, and UI. Confidence: 0.6
